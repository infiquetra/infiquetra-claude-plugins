### CORR-20 — A reused Claude pane whose input box is empty is now a hard stop, because a prompt echo above it wins the marker scan

- **Lens / dimension**: `correctness` / `intent-behavior-completeness`
- **Location**: `plugins/agent-launcher/skills/agent-launcher/scripts/launcher.py:741`
- **Confidence**: 100 · **Pre-existing**: False

The repair changed the marker scan from last-marker-line-wins to last-non-empty-marker-line-wins. Executed against the frozen blob, a pane holding an earlier submitted prompt above an empty live box returns that earlier prompt at cbc2fa19 where cycle-1 code returned empty. Driven end to end, guard_reused_pane raises a stop reporting 27 characters of staged input and writes input_box staged with a 27-character count into the receipt for a box that is empty, so the durable artifact carries a false statement about the session. The comment retained at launcher.py:682-683 states the opposite rule and names this precondition explicitly. A sibling lens measuring 44 live herdr panes found zero false stops in practice, because Claude renders its scrollback echo styled-and-closed, which the extractor reads as empty; the shape is reachable for an unstyled echo but was not observed on any live pane, which materially narrows the exposure without removing it.

**Suggested fix.** Decide the box positionally rather than by emptiness: the composer is the last marker row on screen, and its emptiness is then the answer. Defend the decoy shapes with a positional constraint instead of skipping empty rows, and rewrite or delete the contradicting comment.

### DOC-21 — A sentence the repair added says the receipt has no reasoning-effort value; the receipt carries it under variant

- **Location**: `plugins/agent-launcher/skills/agent-launcher/SKILL.md:82`

The repair introduced the clause that the receipt carries no reasoning-effort value at all. The effective variant is the unit's variant or its effort, and it lands in the receipt under the variant key, so a Codex probe launched with a high effort emits that value. For an OpenCode unit the same key is also appended to the confirmed-against-the-multiplexer list, a reasoning tier read back out of the live session, which is the single strongest read-back the whole preflight produces. **Suggested fix.** Replace the clause: the reasoning effort is recorded under the receipt key variant; for OpenCode it is confirmed against the session, and for every other vendor it is the request echoed back and listed as requested-only. Add that key to the read-back selection.

### SEC-20 — The rule picking the composer line uses a different notion of empty than the rule reading it, so the guard still calls a box holding text empty

- **Lens / dimension**: `security` / `input-trust-boundaries-injection`
- **Location**: `plugins/agent-launcher/skills/agent-launcher/scripts/launcher.py:741`
- **Confidence**: 100 · **Pre-existing**: False

The winning line is chosen by _composer_line_content, which strips ANSI and asks if anything remains; the staged text is then read only from runs outside styled spans. A line entirely styled with a span closing at end of line passes the first test and fails the second, so it wins selection and then reads as empty. Executed against the real guard: for the pane dump '❯ deploy the prod key now' followed by the repository's own captured codex placeholder row, guard_reused_pane returned normally and recorded input_box empty, meaning launch proceeds and the dispatched task concatenates onto the operator's unsent line. **Suggested fix.** Make selection use the extractor's own definition of non-empty: choose the last marker line whose unstyled content is non-empty rather than its ANSI-stripped content. Separately, treat a blank marker row plus following unmarked rows as one composer block.

## The declared residual — three-way judgement, unanimous

The caller declared one residual and asked for a judgement rather than silence: a composer line fully
styled with its span closing at end of line is structurally identical to a vendor placeholder, and both
now read as empty.

**All seven lenses that govern it judged the same way: the right trade, not a blocker, record it rather
than repair it.** The reasoning converges from three directions:

- **Correctness**: the two shapes are byte-identical, and treating a closed span as staged makes every
  idle Codex session a hard stop, which a named test exists to prevent.
- **Testing**: it is untestable by construction — no assertion can separate the two — so the trade has
  to be made in code, with a known-placeholder table, or accepted. What is missing is a named negative
  control so a future reader can tell it was a decision rather than an oversight (TEST-31, P3).
- **Reliability**, measuring live: across all 44 herdr panes on this machine the parser produced one
  true stop and zero false stops, because Claude renders a box holding typed text completely unstyled
  while rendering its scrollback echo styled-and-closed. The styling filter does real discrimination.

**Security supplies the one qualification that matters**: the trade itself is right, but that same
ambiguity must not also decide *which* line is the box. In the extractor the failure is a noisy stop;
in the selector it is a silent dispatch. That is SEC-20.

**Architecture and documentation-clarity block on the silence, not the trade.** The limit has no
`DECISIONS.md` entry, `SKILL.md:36` states the discrimination as absolute, and the released
`CHANGELOG.md:14` repeats it with no caveat at all.
