## Findings

### P0

**#1 — The style's closing block is invisible to the metric that scores it.**
`plugins/house-style/output-styles/house-style.md` prescribes a closing line reading
`Your call: <pre-committed branches>` and names "Let me know how you want to proceed" as the phrasing
that fails its rule. Run against `tools/output_style_scorer.py`'s `CLOSING_ASK_RE`, all three
prescribed forms return `False` and the named counter-example returns `True`. Two of the eight Success
Criteria are computed from that detector, both marked "Up, substantially". Full compliance would have
driven them toward zero and a working rollout would have arrived as a regression.
*Fixed:* detector widened to cover the pre-committed-branch forms its own definition claims to count;
movement on the frozen window measured at 5 turns and disclosed.

## Rejected findings

**Tightening `BARE_ID_RE`.** The lens is right that it matches any 7-to-10 digit number and words like
"defaced". It is not fixed here: `bare_identifier_rate` is one of the nine frozen baseline metrics, and
changing its detector would make the after-measurement incomparable with the only pre-style record that
exists. The overmatch is documented as a heuristic in the metric's own definition string. Deferred as a
choice, not an oversight.

**Making `--until` inclusive of its final day.** The lens is right that the flag says "inclusive" and
excludes that day's traffic. Changing the boundary now would silently redefine the window the frozen
baseline was measured over. *Fixed the other way:* the help text now states exactly what the flag does.

**`git -C <owner/repo>` in the emitted verifier protocol.** Real, and it cannot resolve as a path. It is
**pre-existing** — present at `f6436f6e` before this branch — and the three verifiers in this run
reported successfully regardless. Fixing it means deciding the semantics of `spec.repo` across every
saga workflow, which is a change with a blast radius this pull request was deliberately sized to avoid.
Recorded for follow-up.
