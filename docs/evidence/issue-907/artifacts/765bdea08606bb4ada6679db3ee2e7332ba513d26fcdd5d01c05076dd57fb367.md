## The two questions the brief asked to be scored hardest

### 1. Is the write-site enumeration complete, and does the structural test enforce it?

**The enumeration is complete. The test that guards it is not a structural guarantee.**

Four lenses and the controller independently confirmed the enumeration itself: every `"herdr"`
literal in both scripts is accounted for, exactly two write doors exist (`launcher.py:1690`
`herdr agent prompt` and `launcher.py:1712` `herdr pane run`), both live inside `PaneWriter`,
Orchestrate owns no door, and `agent_argv` carries no prompt so the wrapper create does not
write text. There is no sixth door in the shipped code.

The test is the problem. `_raw_door_calls` (`test_launcher_contract.py:2578`) requires an
`ast.Name` callee spelled exactly `run` whose first positional argument is an inline `ast.List`
whose first three elements are string constants. `_writer_write_calls` requires a receiver that
is an `ast.Name` whose id is literally `writer`. The inline-predicate check requires an
`ast.BoolOp`.

The controller wrote a new unguarded raw pane-write door into `launcher.py` in ordinary refactor
form — `cmd = ["herdr", "pane", "run", str(pane_id), text]` then `run(cmd, ...)` — and ran the
suite. `test_every_pane_write_goes_through_the_one_writer` reported **1 passed**; the full
launcher suite reported **269 passed**. Nothing observed it. The testing lens drove twenty-eight
shapes through the real test and killed five, all of them shapes the repair author had mutated
himself.

Separately, architecture-maintainability and documentation-clarity each demonstrated that
`PaneWriter._raw` is reachable from outside `write`: Python's single underscore is a naming
convention, so any future function can construct a writer and call `_raw` directly, performing
the raw write with no `should_guard_pane_write` call and no detection. That is a second, distinct
route through the same guarantee, and it is the exact shape the repair ledger says was used to
force each site's guard off during verification.

Two supporting facts complete the picture. The comment introducing `PANE_WRITE_SITES` names
`test_forcing_the_guard_off_at_each_write_site_is_observed` as running "below" and turning every
row's guard off independently. That name occurs exactly once in the repository: in the comment.
And the `DECISIONS.md` entry `{#907-pane-writer-owns-the-write-rule}` cites that same per-site
mutation run as its acceptance evidence.

**A negative result, reported as one.** The controller hypothesised that the `wrote_before` flag
had merely moved from the call sites to the writer's construction, where a future site could
forget it. It has not. Both construction seeds are pinned behaviourally: flipping Orchestrate's
sender to `wrote_before=False` kills 4 tests, and flipping `redeliver`'s kills 10. Section 4d of
the brief is satisfied, and this part of the restructure genuinely closed the F38–F41 class.

### 2. Is `land`'s exit-code contract complete, or merely inverted?

**Complete as a set of codes; incomplete as a contract.** Three defects:

1. **Precedence is undocumented and inverts consequence.** `return 3` (a landing worktree could
   not be removed) precedes `return 4` (an owed resubmission was not made) precedes `return 2`.
   When a cleanup failure co-occurs with a withheld resubmission, `land` exits 3 and the owed
   action — the entire reason exit 4 exists — is invisible to a caller reading the exit code,
   which is what the command document explicitly instructs ("Read the exit code, not the prose").
   Reproduced by reliability, api-contract and documentation-clarity independently.
2. **`--clean` is silently cancelled.** The reap block sits after `return 3`, so an operator who
   asked for a reap gets no reap and no line saying so.
3. **A third way a resubmission goes unmade still exits 0.** `_resubmit_one` returns False when
   the controller's slot carries operator fix requests; `resubmit_failed` stays False and `land`
   returns 0 against a documented row-0 meaning of "any owed review resubmission was made". The
   repository's own test asserts `cmd_land(...) == 0` in that state.

The pinning test `test_the_documented_land_exit_codes_are_the_ones_the_command_returns` compares
the SET of documented codes to the SET of integer literals in `cmd_land`'s returns. It would pass
with rows 3 and 4 swapped and cannot see precedence at all.

  interception at the Herdr subprocess boundary, so the writer, the ownership rule and the
  composer parse all run for real. Every *semantic* mutant against the guard dies: dropping the
  guard call kills 55 tests, ignoring `wrote_before` kills 22, hardcoding the seed kills 21.
- **The run-file contract works in both directions**, with `UNIT_FIELDS_BY_CONTRACT` binding the
  contract string to the `Unit` field set so a new field cannot ship silently.
- **Six of `origin/main`'s eight unbounded Herdr calls are now bounded**, and a write timeout is a
  named stop that never falls through from the prompt door to the pane door.
- **The operator's staged draft never leaves memory.** `inspection.text` is used only for `len()`;
  no note, receipt, stop message or run record carries a character of it.
- **`PROMPT_UNDELIVERED`, previously terminal, gained a real `redrive` door.**
