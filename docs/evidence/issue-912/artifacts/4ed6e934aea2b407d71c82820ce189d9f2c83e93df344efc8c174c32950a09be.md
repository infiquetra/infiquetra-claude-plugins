## The two P1 defects

**The fail-closed contract is defeated on the mission-control path (`API-23`).** The purpose of this
change is that an unconfirmed brainstorm boundary must not hand off as ready.
`_infer_maturity_from_path` never opens the file, so the same artifact classifies
`pending-confirmation` under saga and `requirements-ready` under mission-control, whose vocabulary
cannot represent the new value at all. The rendered issue body reads `### Handoff maturity /
requirements-ready` and `Use /plan <issue>`. This is disclosed on the branch — in a review document

encodes the decision justifies it as a "safe direction", which holds only for the explicit

another frontmatter key is a sequence item, not a top-level key, but the extractor honours it. A
`tags:` or `history:` list carrying a `maturity` entry is classified from that nested value and
published with a live route past `/plan`. The artifact's author has done nothing wrong.

### Why each finding matters

**1. `API-23` — mission-control's path-only maturity inference bypasses the new fail-closed contract and prepares an unconfirmed brainstorm boundary as requirements-ready with a live /plan route** (P1, api-contract, `plugins/mission-control/scripts/sdlc_manager.py:4475`)

The stated purpose of this change is that an unconfirmed brainstorm boundary must not hand off as ready. _infer_maturity_from_path never opens the file, so for the same artifact saga classifies pending-confirmation and mission-control classifies requirements-ready. Because --maturity is documented as an override ('Override inferred handoff maturity', sdlc_manager.py:6794), the ordinary 'issue prepare --from <path>' invocation uses the inferred value, which passes the five-value choices tuple and is stamped into the issue body. The prepared issue then instructs /plan, which is exactly the route the fail-closed contract exists to prevent. mission-control's vocabulary cannot represent the new value at all.

*Suggested fix:* Either have mission-control call saga's infer_maturity rather than maintaining a second path-only implementation, or make issue prepare refuse to infer for a source under a SOURCE_DIRS marker and require an explicit --maturity. Separately, correct the exclusion map's justification: it currently claims a safety property that covers only one of the two paths.

*Evidence:* Controller reproduction at 3995ae18, running both implementations against the same fixtures. Artifact declaring pending-confirmation: mission-control 'requirements-ready' vs saga 'pending-confirmation'. Artifact declaring an invalid value: mission-control 'requirements-ready' vs saga 'unknown:unrecognized:bogus-value'. Declaration outside a fence: mission-control 'requirements-ready' vs saga 'unknown:carrier:plan-ready'. All three diverge.; mission-control _HANDOFF_MATURITY_CHOICES is ('idea-ready','requirements-ready','plan-ready','resume-ready','deferred-context') -- five values; 'pending-confirmation' in it is False, while saga's HANDOFF_MATURITIES carries all six.; End-to-end render confirmed by the controller: _render_handoff_context(inferred, artifact) for the pending-confirmation file emits '### Handoff maturity / requirements-ready' and '### Suggested next action / Use `/plan <issue>` to create an implementation plan.'; DISCLOSURE STATUS, checked by the controller rather than assumed: this IS disclosed on the branch, at docs/reviews/2026-08-30-issue-912-saga-brainstorm-improvement-integrated-code-review.md under the heading '### 2 — The defect B1 exists to fix is still live on the Mission Control path'. **2. `AM-35` — A nested YAML sequence item is read as a top-level declaration, so an ordinary artifact with a list in its frontmatter is routed at the wrong maturity** (P1, architecture-maintainability, `plugins/saga/scripts/handoff_envelope.py:167`)

The comment at :167-169 asserts 'A bullet at column 0 is a top-level list item and counts as a visible declaration'. **6. `SEC-16` — Three YAML-valid spellings of a top-level maturity key are invisible to the line scanner, so a declared pending-confirmation routes live** (P2, security, `plugins/saga/scripts/handoff_envelope.py:60`)

The extractor accepts a declaration only when the raw line carries the literal byte prefix 'maturity:' at column 0.
