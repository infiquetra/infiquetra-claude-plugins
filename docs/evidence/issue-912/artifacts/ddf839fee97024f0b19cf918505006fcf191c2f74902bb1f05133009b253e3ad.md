### Why each finding matters

**1. Release note names the wrong shipped plugin version** — `DOC-21`, `plugins/saga/CHANGELOG.md:7`, lens `documentation-clarity`, P2, confidence 100

The entry under the 0.151.0 heading ends by saying the plugin version bumps 0.149.0 to 0.150.0 in the same release so a consumer pinning the plugin version cannot receive the two envelope contracts under one identifier. The whole sentence exists to tell a consumer which version to pin for the schema 1.1 contract, and it names a version an unrelated run shipped, which does not carry this change. A reader following the release note pins the wrong version and gets the old contract, which is the precise failure the sentence claims to prevent. This is not a claim that the release version is wrong: the manifest, the marketplace entry, the heading and the drift guard all agree. The defect is that the prose inside the entry contradicts its own heading, because the release commit moved the heading and the guard but not the body text.

Evidence: `plugins/saga/CHANGELOG.md:7`; `a heading grep prints the 0.151.0 and 0.149.0 sections only; no 0.150.0 section exists`; `plugins/saga/.claude-plugin/plugin.json:3 declares 0.151.0`; `tests/test_saga_plugin.py:48 asserts 0.151.0`; `the release commit changed only the test file`

Suggested fix: Replace the version pair in the entry body with the shipped one and note that the intervening version was taken by an unrelated run.

**2. Decode recovery flips on file byte-length parity** — `API-16`, `plugins/saga/scripts/handoff_envelope.py:42`, lens `api-contract`, P2, confidence 100

The new decode-retry loop tries UTF-16 before falling back to replacement decoding. A non-UTF-8 file with an even byte count decodes as UTF-16 into mojibake, the maturity guard misses, and the reader returns the unreadable sentinel; the identical document with an odd byte count reaches the replacement decode and returns its declared value. Executed: an artifact declaring plan-ready with a latin-1 body routes live at 37 bytes and is blocked as unreadable at 38. A published contract value and the presence of a route therefore turn on a semantically meaningless property, so a consumer cannot reproduce the envelope from the document. The direction is fail-closed, so this blocks valid artifacts rather than routing parked ones.

Evidence: `plugins/saga/scripts/handoff_envelope.py:42`; `plugins/saga/scripts/handoff_envelope.py:57`; `probe: len 50 even returns the unreadable sentinel, len 51 odd returns pending-confirmation, len 52 even unreadable, len 53 odd pending-confirmation`; `probe: a plans artifact at 37 bytes returns plan-ready with a route, at 38 bytes returns the unreadable sentinel with no route`; `tests/test_handoff_envelope_maturity.py:483`

Suggested fix: Attempt UTF-16 only when the bytes carry a UTF-16 byte-order mark, so an unmarked non-UTF-8 file always reaches the replacement decode and its declared maturity is read deterministically. Correct the comment asserting the latin-1 case still returns the frontmatter value, true only for odd-length files, and replace the accidental 47-byte fixture with one pinning the same document at both parities.

**3. Unterminated block with blank value misnames the fault** — `AM-17`, `plugins/saga/scripts/handoff_envelope.py:90`, lens `architecture-maintainability`, P2, confidence 100

The unterminated-block arm returns the bare empty string when the declared value is blank, which is the shape reserved for a well-formed block with a blank value. The two are indistinguishable, and the diagnostic names the vocabulary and never the missing closing delimiter. An operator or agent following it edits the value and the artifact still fails, exactly the failure mode the carrier diagnostic was repaired for, left unrepaired in the sibling arm. The repository-wide vocabulary guard does not compensate: it skips any file whose block is unterminated.

Evidence: `plugins/saga/scripts/handoff_envelope.py:90-91`; `probe: an unterminated block with a blank key and a well-formed block with a blank key produce identical values and identical diagnostics`; `tests/test_handoff_envelope_maturity.py:526-528 skips a file whose block is unterminated, so it is never flagged`

Suggested fix: Return the unterminated-distinguished sentinel with an empty tail rather than the bare empty string, matching the carrier arm's handling of the same blank case, so the unterminated diagnostic fires.

**4. Frontmatter extraction triplicated with divergent rules** — `AM-19`, `plugins/saga/scripts/handoff_envelope.py:137`, lens `architecture-maintainability`, P2, confidence 100

The key-line extraction now exists in three near-copies, one per reader arm, and they have already diverged: the carrier arm omits the inline-comment strip the other two perform, so a carrier declaration with a trailing comment produces a sentinel with the comment quoted back at the operator. Separately, the marker tuple restates the source-directory constant as bare names, and the same six directories are restated again in the path-rule chain, in the lifecycle inference, and in the repository-wide guard's own list. Adding or renaming one source directory means four coordinated edits in this file plus one in the tests, and any missed copy fails silently.

Evidence: `plugins/saga/scripts/handoff_envelope.py:14-21 and :137`; `probe: the marker tuple and the source-directory names are set-equal, so one restates the other`; `probe: a delimited declaration with a trailing comment strips it; the carrier form does not`; `tests/test_handoff_envelope_maturity.py:511-513 restates the six directories a fifth time`

Suggested fix: Extract one declared-value helper used by all three arms so the comment and quote stripping cannot diverge, and derive the marker tuple from the source-directory constant instead of a second literal.

**5. Colliding re-anchored subpath reads a different file silently** — `CORR-18`, `plugins/saga/scripts/handoff_envelope.py:144`, lens `correctness`, P2, confidence 100

When the re-anchored subpath exists under the declared root, the caller-named absolute file is never opened and no diagnostic records the substitution: the envelope's source names one file while the maturity is read from another. A named artifact whose own declaration is non-routable therefore emits a runnable prepare command carrying the other file's value, the same live-route failure the prior P1 named, now under a collision trigger. This is highly reachable in this repository, which keeps dozens of worktrees of the same checkout carrying identically named artifacts.

Evidence: `plugins/saga/scripts/handoff_envelope.py:143-155`; `executed against two real checkouts on this machine: the named file declares an out-of-vocabulary value that must fail closed while the working-directory copy declares a routable one; the envelope emitted the routable value attributed to the named path`; `synthetic second arm: a local copy with no maturity and a named absolute copy declaring the parked value produced a runnable prepare command`; `tests/test_handoff_envelope_maturity.py:167-194 pins the substitution as intended, so the precedence is settled design; the silence is not`

Suggested fix: Keep the precedence but stop misattributing which file was read: set the envelope source to the path actually read, or emit a diagnostic naming both paths.
