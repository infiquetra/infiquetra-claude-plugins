# Frame 6 — Constraint Flipping — Candidate Set

Run 2e71b34e. Ten candidates, each generated by inverting one constraint to an extreme,
then landing on something buildable under the operator's four settled decisions.

Axis spread: A1 ×2, A2 ×2, A3 ×2, A4 ×2, A5 ×2.

---

## 1. The Forty-Word Constitution

- **summary** — Flip the prompt budget to zero: if the style could be only forty words, which
  rule survives? The counter-sample answers it — verdict first, ask last, nothing declarative
  trailing. Write that forty-word core once and paste it **byte-identical** into the head of
  every style in the set, then add a test that asserts the byte-identity across all files. This
  is the only shared-base mechanism that actually exists, because an output style is a single
  Markdown file with no include, import, or inheritance mechanism.
- **axis** — A4 Style architecture and lifecycle
- **basis** — `reasoned:` The operator accepted a stated risk in settled decision 3: "a rule
  only lives in the active style — switch styles, lose it, unless every style shares a common
  base." Every solution to that risk is either (a) a shared file the styles reference, which the
  format does not support, (b) a build step that concatenates a base into each style at package
  time, which adds a generator and a drift window between source and shipped artifact, or (c)
  duplication. Duplication is normally the wrong answer because duplicated text drifts. But
  drift risk scales with the size of the duplicated block. At forty words, a human reads all N
  copies in ten seconds and a five-line test comparing the first paragraph of each file to a
  fixture makes drift impossible. The flip to zero budget is what forces the block small enough
  for duplication to become the *correct* engineering answer rather than a concession.
- **why_it_matters** — It converts the one risk the operator explicitly accepted from an
  ongoing hazard into a solved problem, and it does so without introducing a build step that
  the marketplace plugin would then have to carry. It also settles what the styles are allowed
  to disagree about: everything except those forty words.
- **meeting_test** — The team has to agree on which forty words earn the slot, and that
  argument is the whole style set in miniature.

Draft of the block, for argument's sake:

> Open with one bolded sentence stating what is true now. Close with one line stating what you
> need from the operator, or that you are holding for them. Put nothing declarative after that
> line. Name what a thing is before you name its identifier.

## 2. Few-Shot Pairs Drawn From the Operator's Own Transcripts

- **summary** — Flip the prompt budget to unlimited: at ten thousand words you stop writing
  rules and start showing worked examples, because rules under-specify and examples pin
  behavior. What that reveals is that the short version is missing demonstrations, not more
  rules. The buildable landing is three to five verbatim response pairs — a real reply that
  drew a complaint next to a real reply that drew forward progress — quoted from the operator's
  own transcripts and embedded in the style at roughly four hundred words.
- **axis** — A1 Turn shape
- **basis** — `direct:` The grounding already contains the labeled dataset: ten antecedents to
  satisfied or forward-progress replies (ten of ten open with a bolded one-sentence verdict,
  ten of ten close with a single concrete ask) and nine traced complaint antecedents with a
  six-category failure taxonomy. Both sets are real messages from this operator's corpus, and
  the discriminator between them is already known to be structural placement rather than
  length (835-4,197 chars vs 2,060-4,462 — overlapping) or formatting (headings and tables
  inconsistent in both).
- **why_it_matters** — Nearly every published output style is a rule list, because authors
  assume the budget is tight and examples are expensive. This operator is in the unusual
  position of owning a pre-labeled corpus of their own reactions, which makes few-shot the
  cheapest available specification of "verdict-first, ask-last" — a phrase that a rule list
  can state but cannot disambiguate. It also inoculates against the failure the rule list
  cannot catch: a response that technically opens with a verdict but buries the ask in the
  middle.
- **meeting_test** — Choosing which three of the ten satisfied replies to quote is a decision
  about what "good" means here, and it should be made by the team rather than by whoever
  drafts the file.

## 3. A Shared Agent Preamble in the Symlinked `agents/` Directory

- **summary** — Flip the fifty-seven percent subagent surface: what if output styles reached
  subagents perfectly? You would write a *shorter, stricter* style for them, because a subagent
  has exactly one reader (its parent) and one job. The achievable version today does not
  involve output styles at all — it is a fixed preamble block placed at the top of every agent
  definition file in `~/.claude/agents/`, which the work configuration already symlinks, so one
  edit governs both configurations.
- **axis** — A5 Reach beyond the main thread
- **basis** — `direct:` Two facts combine. First, output styles provably do not reach subagents:
  the `★ Insight` callout appears 315 times in main-thread messages and 7 times in subagent
  messages (98:2), and the binary namespaces prompts as
  `repl_main_thread:outputStyle:<name>` while agents resolve to a separate `agent:custom`
  identifier. Second, `~/.claude-company` symlinks `agents`, `commands`, `hooks`, and
  `CLAUDE.md` to `~/.claude`, while `skills`, `plugins`, `projects`, and `settings.json` are
  separate. The agent definition body is the subagent's own system prompt, so it is the one
  writable surface that reaches the majority of assistant text and is already unified across
  both configurations.
- **why_it_matters** — Fifty-seven percent of all assistant text — 17,922 messages against
  13,665 — is generated where no output style has any effect. Any style set that ignores this
  governs a minority of the output. This move addresses it with a filesystem link the operator
  already made, and it sidesteps the marketplace plugin entirely, so it can ship before the
  plugin does. The cost is real and should be named: agent definitions are edited per file, so
  N files carry the block, which is the same duplication problem candidate 1 solves with a
  byte-identity test — the same test can cover both.
- **meeting_test** — This is the only candidate that reaches the majority surface, and it also
  raises a scoping question the team should settle: does the preamble mirror the main-thread
  style, or is a subagent's contract deliberately different?

## 4. Subagent Payloads Get Translated, Never Pasted

- **summary** — Flip the reader count to zero — every consumer is another agent. That flip is
  already true for the 57% surface, and it exposes a boundary failure: an agent-shaped payload
  crossing into a human-facing reply without translation. Two rules follow. In the parent's
  output style: a subagent's returned text is source material and never appears verbatim in a
  main-thread reply. In the parent's spawn prompt: state the return contract explicitly, so
  the payload arrives in a shape that is cheap to translate.
- **axis** — A5 Reach beyond the main thread
- **basis** — `direct:` Of the 40 "mountain of text" messages (over 4,000 chars with no table,
  diagram, or code — 0.25% of main-thread traffic), one of the three worst was literal
  unformatted JSON: a 12,347-character subagent findings payload dumped into a main-thread
  reply undigested. This is not a formatting preference; it is a specific, observed, traceable
  failure at the agent/human boundary. The spawn-prompt half is `reasoned:` — the parent's own
  system prompt governs the parent, and the text the parent writes into an Agent-tool call is
  ordinary output subject to that prompt, so a rule about spawn text is enforceable through
  the one surface a style does control.
- **why_it_matters** — It is the one place where the 57% problem leaks into the 43% the style
  governs, which makes it fixable *without* solving the reach problem at all. It also names
  the mechanism behind the worst measured formatting failure rather than treating that failure
  as a general verbosity issue, which a length rule would have addressed wrongly.
- **meeting_test** — It defines the contract between candidate 3's preamble and the
  main-thread style; those two have to be designed as a pair or neither works.

## 5. A Published Controlled Vocabulary, Not a Personal Blacklist

- **summary** — Flip the reader count to a thousand — the operator's whole organization adopts
  the style. Every idiosyncratic prohibition ("stop saying vacuous") stops generalizing, and
  you are forced onto rules stated as observable substitutions rather than personal taste.
  Adopt a subset of ASD-STE100 Simplified Technical English as the word-discipline layer: one
  word one meaning, a mandated verb per concept, active voice naming the actor, noun clusters
  capped at three words.
- **axis** — A2 Word-level discipline
- **basis** — `external:` ASD-STE100 Simplified Technical English, adapted as a Claude output
  style in gist L1nefeed/4164ecaaf77879e76dca3c06f142f1c2 — mandated verbs to kill synonym
  rotation ("check" not "verify", "start" not "initiate"), active voice with the actor named,
  ≤20 words per instruction sentence and ≤25 per explanation, noun clusters capped at three
  words. Reinforced by `reasoned:` — a blacklist has N=1 coverage per entry. "Vacuous" drew a
  complaint on 2026-07-26 ("stop saying vacuous and be more descriptive... more like a
  developer, less like an academic"). Banning that one word does nothing about the next
  academic register word, and the operator will have to file a new complaint for each. A
  controlled vocabulary inverts the polarity: instead of enumerating what is forbidden, it
  enumerates what is permitted, which covers the unenumerated cases by construction.
- **why_it_matters** — Seed 3 ("excessive abbreviations... I think I have some things related
  to this in my global claude.md file already") points at rules the operator has already
  written by hand, one complaint at a time. This replaces that reactive loop with a forty-year-
  old aerospace standard built for exactly this problem, and it is the best-matched prior art
  the research pass found for that seed.
- **meeting_test** — Adopting an external standard wholesale versus cherry-picking four of its
  rules is a real fork with different maintenance costs, and it is the team's call.

## 6. The Middle Must Be Skippable

- **summary** — Flip the operator's attention to zero: they read only the first line and the
  last line and nothing between. The rule this yields is not "put the verdict first" — that is
  already known — it is the stronger and previously unstated constraint that **no fact may
  appear only in the middle if it would change the ask**. Make it a testable self-check: delete
  every line but the first and last; if the surviving two lines would mislead, rewrite them.
  The last line additionally carries ownership — whether the next move is the operator's or the
  agent's.
- **axis** — A1 Turn shape
- **basis** — `reasoned:` The counter-sample establishes placement as the discriminator (10/10
  verdict-first, 10/10 single concrete closing ask, nothing declarative trailing). But
  placement rules are satisfiable by a response that opens with a verdict, closes with an ask,
  and hides the load-bearing caveat in paragraph four — which is exactly failure category 4,
  "dense technical wall, no plain framing," 2 of 9 traced complaints. The zero-attention flip
  is what converts a placement rule into a *sufficiency* rule: the first and last lines are not
  merely the right slots for the verdict and the ask, they are the entire guaranteed-read
  budget. The ownership half is grounded in `direct:` evidence — the two human prompt modes
  observed across every repo are approval/continuation ("go ahead", "approved") and status
  check ("where are we with X"), which are both the same question: is this waiting on me?
- **why_it_matters** — Closing failures are the single largest category, 5 of 9 traced
  complaints, and only 3 of 395 sessions (0.76%) end with any summary or next-step signal.
  Seed 5 asks for "what's complete and what's next." The skippability test is what stops that
  from degrading into a boilerplate footer that restates the middle, and the ownership marker
  is what makes the closing line actionable to someone supervising a fleet across five or six
  workstreams.
- **meeting_test** — The skippability test is a self-check the model performs before sending;
  whether a style can reliably induce a pre-send check at all is worth arguing before it goes
  in.

## 7. Every Verdict Sentence Carries Its Evidence Grade

- **summary** — Flip trust to zero and every claim needs an inline receipt, which is
  unreadable. Flip trust to total — the operator never reads the body, only acts on the closing
  ask — and the ask must be safe to act on blind. Both extremes converge on the same rule: the
  verdict sentence states its grade. Verified (name the command, query, or file that produced
  it), inferred (say so), or unknown (say so). Not a section, not a table — a clause.
- **axis** — A2 Word-level discipline
- **basis** — `reasoned:` The zero-trust extreme fails on volume: median main-thread message
  length is 142 characters, so per-claim citations would multiply the routine turn several
  times over for no gain. The total-trust extreme fails differently: if the body is unread,
  an ungraded verdict is indistinguishable from a graded one at the moment of action. The
  intersection of what survives both extremes is a single graded clause attached to the
  verdict only — the one sentence guaranteed to be read under candidate 6. This candidate also
  sits on the boundary of settled decision 3 and the team should see that explicitly:
  *verifying before claiming* is policy and stays in CLAUDE.md's Validation Discipline
  section; *how a graded claim is worded* is presentation and moves into the style. If the
  team disagrees with that split, this candidate does not surface — but the split itself needs
  a ruling either way, because Validation Discipline is the largest CLAUDE.md section with a
  presentation surface.
- **why_it_matters** — Verification callouts are approximately zero in the friction data,
  which reads two ways: either the discipline is working, or the operator cannot tell an
  extrapolation from a measurement and therefore never files the complaint. The grading clause
  makes the difference visible at the exact position the operator is guaranteed to read.
- **meeting_test** — It forces a ruling on where the policy/presentation line falls, which
  every other candidate that touches CLAUDE.md depends on.

## 8. Only Line-Independent Visual Forms

- **summary** — Flip model capability upward: if the model followed any instruction perfectly,
  you would ask for aligned box diagrams, matched column widths, and swimlanes. The flip
  reveals that the reason those are absent is not authorial shyness — it is a measured
  capability floor. So whitelist the forms whose correctness is *line-local*: indented file
  trees, single-line arrow chains (`a -> b -> c`), Markdown tables (the renderer does the
  alignment, the model only supplies consistent cell counts), and numbered step lists. Ban
  forms requiring a character on line 3 to align with a character on line 9.
- **axis** — A3 Visual form selection
- **basis** — `external:` ArtPrompt (ACL 2024, arXiv 2402.11753) measured GPT-4 at 25.19%
  accuracy on single-character ASCII-art recognition, and the research pass found **no
  validated prompt-only technique for preventing width drift** — the IoTeacher ASCII dashboard
  gist, which prescribes a four-zone layout, has no drift-prevention technique either and
  lists "overusing borders until content becomes hard to scan" among its own anti-patterns.
  Corroborated by `direct:` measurement — of ~30 genuine diagrams in 16,029 main-thread
  messages, the shapes actually in use are file trees and small dependency chains. Not
  flowcharts, not sequence diagrams, not state machines. The corpus already converged on the
  line-independent subset without being told to.
- **why_it_matters** — Seed 2 asks for "pictures, graphs, tables over a mountain of text," and
  the operator asked for pictures five separate times, always when already lost. A style that
  grants that request without a form whitelist will produce box diagrams that drift, which is
  worse than prose because a misaligned diagram costs reading effort *and* trust. This gives
  the operator the pictures they asked for in the forms the model can actually render, and it
  states the reason so the whitelist can be revisited when the capability floor moves.
- **meeting_test** — The whitelist is a hard product decision — it tells the operator that
  some pictures they may want are permanently off the menu — and that needs their sign-off,
  not a drafter's.

## 9. Diagram Syntax Is Keyed to Destination, Not to Preference

- **summary** — Flip seed 1's premise: what if Mermaid were always the right choice? It is —
  whenever the bytes land in a file that a renderer will read. The measured data says the
  operator's Mermaid complaint is not about a main-thread habit at all. So the rule is not
  "never Mermaid"; it is destination-keyed. Bytes going to the terminal use the candidate 8
  whitelist. Bytes going into a file, a pull request body, or an artifact use Mermaid, because
  that is where it renders.
- **axis** — A3 Visual form selection
- **basis** — `direct:` A Mermaid fenced block appears in rendered main-thread text in **7 of
  16,029 messages (0.04%)** — seed 1's premise is not supported at the main-thread level.
  Mermaid concentrates in subagent traffic (119 messages) and in file contents Claude reads or
  writes (roughly 23 of 30 assistant-line hits are Write or Edit payloads). The verbatim
  complaint on 2026-07-17 in `campps-context-library` — "you always do that... I am in cli, you
  waste tokens generating mermaid. stop doing that" — is real, but it is pointing at the
  subagent and file-write surfaces, not at the main thread.
- **why_it_matters** — A blanket Mermaid ban is the obvious reading of seed 1, and it would be
  actively harmful: it would degrade the saga documents, engineering journal entries, and pull
  request bodies where Mermaid is the correct choice and renders properly, in exchange for
  fixing 7 messages out of 16,029. This is the clearest case in the run of a seed that only
  makes sense under a constraint that does not hold — and the correct fix routes through
  candidates 3 and 4 (the subagent surface), not through a main-thread prohibition.
- **meeting_test** — It contradicts a seed the operator stated in their own words, with data,
  and the operator should hear that argument directly rather than have it resolved silently.

## 10. A Headless Fixture Suite That Proves the Style Is Live

- **summary** — Flip the failure cost to catastrophic: if a badly formatted response caused a
  production incident, the discipline that appears immediately is a test suite. Build one.
  Drive `claude -p` headlessly over a fixed set of fixture prompts with the style selected,
  and assert the mechanical invariants a script can check: first line is a bolded declarative,
  last line is a question or an explicit hold, nothing declarative after it, no fenced Mermaid
  in terminal-destined output, no bare commit-shaped hex without a nearby explanatory word.
  Add a smoke check that reads back the effective `outputStyle` so a style that silently failed
  to load is caught immediately.
- **axis** — A4 Style architecture and lifecycle
- **basis** — `reasoned:` The mechanics make silent failure the *default* failure mode here,
  and three separate facts stack. A style takes effect only after `/clear` or a new session,
  because the system prompt is read once — so an edit that did nothing looks exactly like an
  edit that worked until the next session. The `/output-style` slash command was deprecated in
  v2.1.73 and removed in v2.1.91, and the operator runs 2.1.224, so selection now lives in
  `/config` writing `outputStyle` into `settings.local.json`, which is typically not committed
  — meaning the committed per-repo selection of settled decision 4 would be the first behavior
  key any of the operator's repos has ever committed (of 18 repos with Claude settings, only 6
  have a committed `settings.json`, and every one sets only `permissions` or
  `worktree.bgIsolation`). And `keep-coding-instructions` defaults to **false**, silently
  removing Claude Code's built-in software-engineering instructions. Every one of those is a
  failure with no error message. Headless invocation is the natural harness because each
  `claude -p` call is a fresh session, which is precisely the condition the style needs.
- **why_it_matters** — Axis A4 names "how the operator would verify a style is working" as an
  open question, and the operator's own standing rule is that a working tree is not a current
  source and "fixed" needs a confirming signal. Shipping a style set through the marketplace
  plugin with no way to confirm it loaded would violate that rule at the level of the tooling
  itself. The fixture suite is also what makes candidate 1's byte-identity test and candidate
  6's structural invariant enforceable rather than aspirational.
- **meeting_test** — It decides whether this ships as a set of Markdown files or as a tested
  artifact, which changes the scope of the whole effort and belongs in the plan, not in the
  drafting.

## Flips run that did not produce a surfacing candidate

Recorded so the reasoning is not repeated later.

- **Number of styles → one, with a runtime mode switch.** Detection is the named weak link:
  orchestration-mode has no reliable file-presence rule (`.saga/` exists in
  `infiquetra-ansible-collections` too, which shows almost no orchestration usage), and
  `talaria`'s ADR signature is temporal and stops firing once it ships code. The flip suggests
  replacing per-repo selection with one self-detecting style. That **violates settled decision
  4** (selection is committed per-repo settings) and does not surface as stated. The
  compatible remainder — a repo picks the style file, and the file carries a short paragraph
  handling the orchestration-versus-direct-ops variance that file detection cannot see — is a
  detail of whichever style candidates survive, not a candidate of its own.
- **Session length → infinite.** Yields the observation that a rule in the style survives
  context compaction while a mid-session instruction does not, which supports settled decisions
  2 and 3 rather than adding anything to them.
- **Time → one hour to author.** Yields "ship the forty words first," which is candidate 1's
  sequencing, not a separate move.
