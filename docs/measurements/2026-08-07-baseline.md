# Output presentation baseline, 2026-08-07

## Why this exists and why the date matters

This is a measurement of how Claude Code's output actually behaves across Jeff's two
configurations — `~/.claude` and `~/.claude-company` — taken **before any custom output style
has been written or enabled**. Once a style ships, every transcript after that point is
affected by it, and there is no way to reconstruct what the unmodified behaviour looked like.
The window for capturing this closed the moment the first style landed, so it was captured
first.

It is the "before" half of the comparison described as survivor 8 in
`docs/ideation/2026-08-07-output-styles-ideation.md`. The "after" half is produced by running
the same instrument again with the same window length.

One caveat that must not be lost: **these numbers were recorded while Claude Code's built-in
`Explanatory` style was active**, not with no style at all. So this baseline measures "current
behaviour", not "unstyled behaviour". Separating those two would require the two-week control
run recorded as open question R6 in the ideation document, which has not been done.

## How to reproduce it

```
python3 tools/output_style_scorer.py \
  --since 2026-07-03 --until 2026-08-07 \
  --exclude /Users/jefcox/.claude/projects/-Users-jefcox-bin/ab04a9a4-1357-4d06-a5f7-7e4e390246c2.jsonl \
  --out docs/measurements/2026-08-07-baseline.json --markdown
```

The `--exclude` is the transcript of the ideation session itself. That session discussed every
complaint phrase at length, so leaving it in would have let the analysis contaminate its own
input.

Tests: `python3 -m pytest tests/test_output_style_scorer.py -q` (29 tests).

### What each one means

**subagent_reach_share — 57%.** The share of all assistant output generated inside a subagent.
Output styles apply only to the main conversation thread, so this is the fraction of output
that no style can change, no matter how it is written. This is the single most important
number here and it is the reason two of the ten survivors exist at all.

**session_closing_ask_rate — 2.70%.** Sessions whose final main-thread message ends on a line
that asks a question, states a pre-committed branch ("if the tests pass I will merge"), or
explicitly hands control back. The other 97% end on a declarative statement, leaving the reader
to work out whether it is their move. This is the target of survivor 1.

**verdict_first_rate — 2.98%.** Messages that open with a bolded plain-language claim. Markdown
headings deliberately do not count: a heading names a section, it does not state a finding.

**turn_closing_ask_rate — 5.53%.** The same closing test applied to every message rather than
only the last of a session. Having both separates two different problems — "we never close
sessions" from "we never close turns". They are close together here, so the problem is general
rather than specific to session endings.

**mountain_of_text_rate — 1.16%.** Main-thread messages of 4,000 characters or more of prose,
excluding tool calls and thinking blocks.

**mermaid_in_terminal_rate — 0.05%.** Main-thread messages containing a mermaid fence, which
renders as raw source in a terminal. Deliberately does not count mermaid written into files,
which is correct behaviour. Seven messages in five weeks.

**bare_identifier_rate — 1.69%, heuristic.** Messages where an issue number, pull request
number, or short commit SHA opens a sentence with no noun saying what it is ("#656 is green"
rather than "pull request #656 is green"). Pattern-matched, so it is a trend line rather than a
verdict on any single message.

**format_complaint_proxy and clarity_complaint_proxy — proxies, not the real rates.** These
count human messages that name a presentation problem *and* carry corrective register. They do
**not** reproduce the 5.6% format and 7.2% clarity figures quoted in the ideation document,
because those came from a human reading all 765 messages and judging each one. A keyword proxy
cannot replicate a judgement. What it can do is fire consistently on future data, so the right
comparison is proxy-to-proxy across runs. The hand-labelled figures are historical context.

## Reconciliation against the ideation document

The ideation document quotes numbers produced by throwaway scripts. This instrument reproduces
some exactly, and disagrees with others. Every disagreement is listed here rather than quietly
resolved.

### Does the mountain-of-text correction change any conclusion?

No. Seed #2 ("pictures, graphs, tables over a mountain of text") was cut as **R3** primarily for
being too vague to action, with the low measured rate as supporting evidence. At 1.16% the rate
is still small, and the primary ground for the rejection is untouched. The intent still survives
in survivors 4, 5, and 10. R3 stays cut.

## A note on how this instrument first failed

On its first run this scorer reported the subagent share as **0%**. The cause was a
non-recursive file glob: main-thread transcripts sit at `projects/<repo>/<uuid>.jsonl`, but
subagent transcripts are one level deeper at `projects/<repo>/<uuid>/subagents/agent-*.jsonl`.
The pattern was seeing 296 of 2,655 files.

This is worth recording because of the shape of the failure rather than the size of it. A
scoring script that breaks usually breaks by finding *nothing*, and a metric reading zero looks
like good news. "0% of output is out of reach" would have been reported as a win. The original
57% survived only because a human already knew the number should be large.

Two defences are now in place: the reach metric is computed by two independent classifiers that
must agree or the report marks itself `SUSPECT`, and the test suite asserts that the walk finds
subagent transcripts at all.
