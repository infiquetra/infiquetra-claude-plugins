## Findings

### F1 — R5 (no-hard-wrap soft-wrap) encoded but not demonstrated in the session's generated docs

**Severity:** low. **Class:** docs.

**Evidence:** `formatting-style.md` rule 5 prescribes no hard wrap within a paragraph for generated output, but the docs generated this session hard-wrap at ~100 chars — `docs/ideation/2026-06-07-saga-doc-readability-ideation.md` maxes at 103 chars per prose line. The templates encode the rule; no pre-existing generated doc exhibits it.

**Why non-blocking:** the core goal of R5 — "viewers don't run paragraphs together" — is already met by blank-line paragraph separation (R1) plus the table render, so the absence of no-hard-wrap does not cause the jumbling the issue set out to fix. The U6 gate deliberately does not enforce no-hard-wrap on template source (KTD3), so this is a presentation-consistency gap, not a functional defect.

**Repro:** `grep -vE '^\||^#|^\s*[-*]|^```' docs/ideation/2026-06-07-saga-doc-readability-ideation.md | awk '{print length}' | sort -rn | head -1` → 103.

**Deferred recommendation:** the next doc generated by any saga skill should exhibit no-hard-wrap; this QA artifact is written that way as the first demonstration. If the repo's hard-wrap habit for committed docs proves to conflict with R5 in practice, that is the documented "revisit when" condition on DECISIONS `{#saga-doc-formatting-contract}`.
