# Golden-fixture convention (fake-adapter integrity)

_Issue #458 · facet T11-F1-6 · advisory rollout_

## Why

A fake is only trustworthy if its fixture data still matches what the **real producer** actually
emits. The repo has already been burned by the opposite (`docs/engineering-journal/LEARNINGS.md`
`{#fake-adapter-hides-real-path-mismatch}`): `FakeWT`'s hand-crafted `git worktree list --porcelain`
fixture was shaped to already match the queried path, so every unit test passed while the real,
realpath-canonicalizing adapter diverged. Nothing mechanically pinned the fake's fixture to reality.

## The convention

Each fake whose behavior depends on a producer's output format pins that format to a **golden
artifact derived from the real producer**, recorded in `tests/fixtures/golden/manifest.json`:

```json
{
  "goldens": [
    {
      "fake": "<which fake consumes this data>",
      "producer": "<the real command/function that generates it>",
      "path": "tests/fixtures/golden/<name>.golden.txt",
      "sha256": "<pinned hash>",
      "note": "<what was normalized for machine-independence>"
    }
  ]
}
```

`scripts/check_fake_fixtures.py` recomputes each golden's SHA256 and flags **drift** — a golden that
was **deleted** (missing file) or **mutated** (hash mismatch). The golden is generated by the real
producer, not hand-authored, and re-derivable:

```bash
# Check for drift (default). Advisory in CI: reports drift but exits 0.
uv run python scripts/check_fake_fixtures.py --check

# Re-derive every golden from its real producer and rewrite the manifest hashes.
# Run this deliberately when the real producer's output legitimately changes.
uv run python scripts/check_fake_fixtures.py --regenerate
```

### Machine-independence

A raw producer capture carries machine-specific volatile values (absolute paths, commit SHAs). The
generator normalizes exactly those axes so the golden is byte-stable across machines/CI while still
being real producer output — e.g. the worktree golden replaces the temp root path with `<ROOT>` and
40-hex commit SHAs with `<SHA>`, but keeps the real `worktree`/`HEAD`/`branch` line grammar and the
blank-line record separator a fake must honour.

## Worked example (v1)

`tests/fixtures/golden/worktree_list_porcelain.golden.txt` — a normalized capture of real
`git worktree list --porcelain` output, consumed by the worktree-liveness fake
(`FakeWT` / `tests/fakes_registry.FakeWT`). Since #588 that consumption is **behavioral, not
declarative**: `scripts/check_fake_fixtures.py` looks the fake up in its `_CONSUMERS` table and runs
`FakeWT.load_porcelain()` against the golden's bytes, so a manifest row naming a fake nobody consumes
(`unpaired`) or a golden the paired fake can no longer parse (`consumer_failure`) is drift in its own
right — alongside the `deleted` and `mutated` hash checks.

`tests/test_check_fake_fixtures.py` proves all four: a mutated or deleted golden is flagged, an
unpaired fake and a consumer failure each turn the check red, the registered `FakeWT` really does
read the committed golden, and the committed golden is byte-identical to a fresh real capture.

## Scope

v1 ships **one** worked pairing. Backfilling a golden for every existing fake is deliberately out of
scope (issue #458 non-goals) — add a manifest entry + golden when a new fake's correctness depends on
a real producer's format.
