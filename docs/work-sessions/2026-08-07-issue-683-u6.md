## Summary

U6 decouples team-execution from the fleet lease broker and renames the liveness
TTL observation from `lease_ttl_seconds` to the source-neutral `ttl_seconds` across
the serialized event schema — all in one commit, as a partial rename would raise
`KeyError` at `liveness_events.py:236` at event-parse time, invisible to mypy.

## Key decisions

- **Whole-file deletion vs edit for `lease_protocol.py`:** Deletion is correct; no
  function survives without the broker. A shim would contradict R1/R2 and require a
  version bump reversal.

- **Caller-asserted identity vs broker-verified:** With the broker gone, the
  `bind_identity` guarantee that "the caller cannot choose digests or generations"
  is deliberately dropped (Scope Decision Option C accepted loss, judgment basis).
  The adapter now validates shape only.

- **Compatibility answer (open question from R4a, now decided):** Previously written
  liveness events do **not** need to parse under the old key. This is a breaking
  single-schema rename; old events with `lease_ttl_seconds` fail closed
  (`evidence-error`). A dual-schema (both keys) would be a separate product
  decision and is not implemented; the stop condition for dual-schema would have
  halted this unit.
